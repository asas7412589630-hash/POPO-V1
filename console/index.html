連線設定

代理要打去哪一台供應商（例：logfare.ai、api.openai.com）。 只填主機名稱，不要 https://、不要路徑。
這跟「設定」的 Base URL 不同：Base URL 是你的客戶端連誰，這裡是代理連誰。
改完要重啟才生效。
填了就永遠只送這個真實模型 id，alias 與備援鏈都不作用。

這是什麼

一個跑在你裝置上的代理。客戶端送 OpenAI 格式的請求進來，它補上破甲提示， 轉送到上游模型，再把回應送回。

流向：你的客戶端 → 這個代理 → 上游模型。
所以「Base URL」填的是這個代理，不是上游。

第一次設定：四個步驟

全部在「設定」頁，一次做完：

1 · 上游 API — 填供應商網址與它的密鑰，按「讀取模型清單」。
網址結尾要 /v1，例如 https://api.openai.com/v1。任何 OpenAI 相容服務都可以。

2 · 選模型與破甲 — 勾要開放的模型，每個指定吃哪一套破甲。
上游的模型名稱各異，所以破甲由你指定，不靠名稱猜。

3 · 對外或對內 — 開過隧道就選對外。

4 · 套用 — 按下去，直接產出 Base URL 和 API Key，複製就能用。
金鑰只顯示這一次，之後無法再印出（伺服器只存雜湊）。

三個名詞別搞混

上游 API 網址
你的模型供應商。只有代理會用到，客戶端不需要知道。
Base URL
客戶端要連的位址 = 這個代理。設定頁產出的那一條。
API Key
代理發給客戶端的鑰匙（triad-…），不是上游的密鑰。
最常見的錯誤：把上游網址填進 Base URL。那樣客戶端會直接打到上游，破甲完全不作用。

破甲怎麼分配

deepseek 家族
角色框架 + 交付契約，約 33,650 字
glm 家族
角色框架 + 交付契約，約 33,650 字
gpt-5.2 家族
輸出護欄 + 交付契約，約 2,230 字
兩套不能互換。GPT 讀到長角色框架會當成操控而拒答；glm / deepseek 少了角色框架則不吃破甲。
程式強制分家，連 X-Armor-Level 也無法跨越。
glm / deepseek 的組合是固定的，不需要也不應該切換。

思考強度

預設不指定，由模型自己決定花多少時間思考。
要指定就到「調校」頁選；選了會覆蓋預設。
上游沒宣告支援程度的模型不會收到這個參數（硬送會被判 400）。
例外：gpt-5.2 有 max_tokens 下限 2000，這是實測必要的值。

上下文與時間上限

上下文管理預設全部關閉（交接／輪替／壓縮門檻都是 0）， 你的歷史原封不動送到模型。要代理幫你管理長對話，再到「調校」填數字。

輸出長度：非 GPT 模型不設上限，要多少給多少。
時間上限：gpt 家族 70 秒，其他模型 300 秒。

記錄頁怎麼看

三層：客戶端 → 對話 → 回合。
對話 id 以 x- 開頭的是客戶端自己指定的（最準）；
c- 是代理用「系統提示 + 第一句」推定的。
點開任一回合可以看到每一次嘗試、重試原因、耗時與用量。
